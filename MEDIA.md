# Media — Maison Ondine

Every photograph, film and 3D model on the site comes from a named **slot**.
Components never point at a file or URL directly, so the house's own
photography can replace any placeholder without touching a component.

## How images work

- Slots are declared in `data/image-slots.ts` (query, orientation, display ratio, purpose).
- `npm run seed:images` runs `scripts/fetch-unsplash.ts` once. It searches the
  Unsplash API, picks the best result per slot (orientation, ≥ 3000 px long
  edge, relevance, likes), calls `links.download_location` once per selected
  photo (required download tracking) and writes `data/images.json`.
- The site reads **only** `data/images.json` at build time. No API calls at runtime.
- Photos are **hotlinked** from `images.unsplash.com` (required by Unsplash).
  `<UnsplashImage>` passes a custom loader to `next/image`, so the srcset is
  built from `urls.raw` + imgix params (`w`, `q`, `auto=format`, `fit=crop`).
  `auto=format` serves AVIF to browsers that accept it, WebP otherwise.
- Attribution: "Photo by … on Unsplash" appears on hover/focus of every image
  (links carry `utm_source=maison_ondine&utm_medium=referral`), and `/credits`
  lists every photo.
- Request budget: the demo key allows 50 requests/hour. 14 searches + 32
  download pings = 46. Searches are cached in `scripts/.cache/`, progress is
  saved after each photo, and the script stops before the quota runs out, so
  re-running an hour later resumes where it stopped.

- Query note: "jewellery atelier" returns 0 results on Unsplash, so the four
  `atelier-*` slots use "jeweler workshop" instead.

### Replacing a slot with the house's own photography

1. Put the file in `public/media/` (or on any image CDN).
2. Change the slot's record in `data/images.json` — or add a local-image
   branch to `components/media/Photo.tsx` — keeping the slot id.
3. Re-run `npm run media:doc` to refresh the table below.

## Composer cut-outs

The composer shows real photographs of jewellery with the background removed,
not 3D renders; the catalogue (`/jewellery`) uses the same cut-outs. Files live in `public/cutouts/` (about 5.2 MB in all) and are
described in `data/cutouts.json` (size, sparkle hotspots, source metal, metal mask).

| File | What it is |
| --- | --- |
| `<design>.webp` | The piece, background removed, trimmed, ≤ 1400 px, WebP with alpha. 13 designs (4 rings, 3 bracelets, 3 necklaces, 3 earrings). |
| `<design>-metal.webp` | Metal mask: alpha = "this pixel is metal". Used to re-tone gold without colouring the diamonds. |
| `stone-<shape>.webp` | Six loose diamonds (round, oval, princess, emerald, pear, cushion), all cropped from one photograph. |
| `p-<piece>.webp` | 19 further catalogue pieces (`data/products.ts`), same pipeline; sources are the `cut-p-*` slots. |

Sources: the 14 `cut-*` slots in the table above (Unsplash licence, download
tracked, credited on `/credits` and on the composer stage). Removing a
background and re-toning are modifications the Unsplash licence allows; the
files are served from this site rather than hot-linked because they are edited.

**How they were made** (`scripts/cutouts/`, run outside the project because the
segmentation model is large):

1. `make-cutouts.mjs` downloads each photo at 2400 px (7200 px for the loose
   diamonds), crops if needed, removes the background with IS-Net
   (`@imgly/background-removal-node`, model "medium"), applies an alpha curve to
   drop the haze of soft shadows, trims, pads, and writes the WebP. Per-piece
   options in `manifest.json`: `crop`, `alpha` [low, high], `whiteKey` (fabric seen
   through a hoop), `saturation` (colour cast from a coloured backdrop).
2. `metal-masks.mjs`: metal photographs as smooth gradients, diamonds as dense
   facets. Texture energy (|L − blur(L)|, blurred) separates them; in gold photos
   colour saturation marks metal too; bright near-white pixels (stones, specular
   highlights) are kept out; a few centre stones are excluded by hand (`KEEP_OUT`).

```
mkdir ../cutout-tool && cd ../cutout-tool && npm init -y
npm i @imgly/background-removal-node@1.4.5 sharp@0.33.5
cp ../Ondine/scripts/cutouts/*.mjs ../Ondine/scripts/cutouts/manifest.json . && mkdir src
node make-cutouts.mjs ../Ondine ./src [design ...]
node metal-masks.mjs ../Ondine [design ...]
```

**Adding a design:** add a `cut-…` slot with a `pick` in `data/image-slots.ts`
and run `npm run seed:images` (download tracking and credit), add the entry to
`manifest.json`, run both scripts, then add the design to `DESIGNS` in
`lib/composer-options.ts` and its price to `MAKING` in `lib/pricing.ts`.

**Replacing them with the atelier's own photography:** shoot each piece on a
plain background in one metal, run the same two scripts, and set `metal` in
`manifest.json` to the metal it was shot in.
